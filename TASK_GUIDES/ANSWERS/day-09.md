## 综合面试情境题
**问题：**用户打断正在说话的数字人，旧LLM回答在新回答之后才返回。只暂停扬声器足够吗？

**参考推理：**不够。需要用turn_id或版本机制让旧LLM/TTS数据无效化，取消旧合成/播放队列并隔离并发状态。网络或LLM旧结果晚到时不能重新入队播放；此外VAD发现声音不等于已正确解析用户意图。危急场景应有授权/确认与人类介入，不应把LLM当医疗裁决器。

## 补充参考解｜语音打断正确的状态演化

~~~text
epoch=1 / turn=T1 -> VAD -> ASR -> LLM -> TTS playing
user_interrupt -> invalidate epoch1, stop TTS queue, cancel downstream
epoch=2 / turn=T2 -> new ASR/intent
late_response(epoch1) -> discard  [NOT SPEAK]
~~~
正确的关键不是“播放键被按停”，而是**端到端失效旧响应**。LLM请求如果无法物理取消，至少用`turn_id/epoch`在消费端拒绝过期结果；音频、字幕和角色动作状态都要同步过期。

**几个容易错的说法**：VAD只判断语音活动，不等于正确识别语义；ASR→LLM→TTS是级联的一种方案，端到端语音模型可以有其他链路；播放自然也不表示情感识别正确。

**异常案例**：单次雷达不可靠时不直接报警；运动干扰多时标“信号未知”；紧急求助优先于普通聊天，但具体联络动作必须尊重协议、授权与实际条件。这里的练习不提供医疗诊断功能。

**报名真实性**：计划把10/28作为建议提交日，不是“已经提交”或“官方最终截止日”；用户确认10/30为截止，回执只有真实页面反馈才能证明完成。

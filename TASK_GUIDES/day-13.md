## 实际任务补强｜两端XR坐标的手算与安全状态机

### A. 先写清变换记号
约定`T_target_source`把**source坐标**中的点变到target系。A端手在其本地坐标`p_A=(0.2,0,0)m`；为方便演示，只用平移：
- `T_shared_A`：A到共享世界，平移(1,0,0)m；
- `T_shared_B`：B到共享世界，平移(3,0,0)m。

让来访者B看到A的手，应求：`p_B = inverse(T_shared_B) * T_shared_A * p_A`。先手算到结果，再查看答案。然后问：如果两端有不同旋转、参考原点还漂移，为什么不能简单相减两个位置？

### B. 分开画“建立通信”和“空间对齐”
通信：`Signaling → SDP Offer/Answer → ICE/STUN/TURN → WebRTC PeerConnection → audio/data`。
空间：`HMD/Hand tracking → local frame → shared anchor / transform → remote avatar pose`。
**WebRTC连通不意味着两个人自然站在空间的同一处；空间锚点对齐也不会自动保证低延迟传输。**

### C. 画带时间戳和置信度的消息
~~~json
{"type":"hand_pose","frame":"A_local","t_ms":123456,
 "tracking_valid":true,"confidence":"measured_or_unknown",
 "pose":{"position_m":[0.2,0,0],"orientation_xyzw":[0,0,0,1]},
 "permission_haptics":false}
~~~
字段用于学习，不是来自真实设备的私密运行数据。对姿态消息设置年龄阈值/丢失规则时，**必须显式声明阈值由产品实验确定，不能凭空说是权威标准**。

### D. 三个必须演练的故障
1. 丢失跟踪但网络正常：禁止基于旧姿态继续触觉/远程机器人动作，进入停止或降级。
2. 跟踪正常但网络抖动严重：插值/平滑与“停止执行”的权衡，老旧姿态不应当即时指令。
3. 用户撤回触觉授权：撤回需高优先级且幂等，不因缓冲区里旧消息重新触发。

**产物**：变换链与逆运算手算、Rove双端通信图、三个降级状态，**当天第二轮不少于45分钟模拟面试**。

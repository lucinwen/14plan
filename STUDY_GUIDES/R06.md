# R06｜Isaac Sim：从“可渲染场景”走向物理/机器人可用（Day06）

**入口**：[NVIDIA Isaac Sim Core API](https://docs.isaacsim.omniverse.nvidia.com/latest/core_api_tutorials/index.html)。它主要处理 USD 场景、物理、传感、机器人模型与模拟，并不等于 Isaac Lab 的策略训练任务定义。

## 应该点什么（50min以内）
1. **Hello World**：看 World / Simulation Context / step 的调用语义，跳过安装和环境搭建细节。
2. **Hello Robot**：找 robot articulation / joint / action / stepping，写出最小输入输出。
3. **USD与物理场景**：关注碰撞体、刚体、关节、质量和单位；漂亮mesh不能代替碰撞和物理属性。
4. **传感器**：至少解释相机/深度/接触等观测如何与仿真时间戳对应。

## 用你熟悉的 UE 经验理解
写一张迁移核查表：`UE Actor/PCG Mesh → USD/Scene Primitive → collision/rigid body → robot/observation → success rule`。逐项填写：
- 单位：厘米还是米？坐标与旋转如何变换？
- 是否有刚体、接触和物理材质？门是否有可驱动关节？
- 机器人是否存在URDF/articulation与碰撞半径？它有哪些动作/观测？
- reset 后是否能恢复初始状态，seed是否保存？
- 如果有导入成功但目标不能抓，属于资产、控制还是评测问题？

## 验收与停止条件
你应能给定一张UE场景图，列**至少12项机器人仿真前置检查**并解释每一项失败的影响。不要强迫自己安装几十GB依赖；当前的可验收成果是正确的数据/评测合同。

**必分清**：[R19 Isaac Lab](R19.md) 的 observations/actions/rewards/terminations/resets 属于学习任务定义；即使Isaac Sim可物理运行，也未证明任何策略成功。

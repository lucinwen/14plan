# R21｜参考空间：从 WebXR 手动对齐理解到 OpenXR（Day13）

**必要的区别**：Belean 当前 Web 软件的 XR 路径是**浏览器 WebXR local-floor/手动对齐**，并非已经构建、测试了完整原生 OpenXR 双设备应用。OpenXR是学习可迁移的参考空间概念，不应将原生API `xrLocateSpace`误称为 Belean Web 原型的既有调用。

**参考来源**：[OpenXR 1.1 Reference Spaces](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#spaces) · [WebXR Reference Space 规范](https://www.w3.org/TR/webxr/#xrreferencespace-interface)。今日优先理解三个参考系、变换链和tracking失效的处理，**不需要读整部规范**。

## 45分钟阅读与操作
1. **10分钟**：VIEW / LOCAL / STAGE / local-floor 等参考空间表示什么；为何局部设备原点不等于跨设备共享原点。
2. **10分钟**：浏览器获得头显/双手位姿是**相对于一个 reference space**；进入新空间时需要自己标定地面位置和朝向。
3. **15分钟**：绘制 `A_local→shared←B_local`，用 `T_shared_A`、`T_shared_B`组合变换；说明旋转与平移次序为什么重要。
4. **10分钟**：写出 `tracking_invalid`、`alignment_reset`、`space_revision_changed` 三个事件各怎样触发旧姿态失效与重新确认。

## 不要混淆以下层次
- **local-floor头部位姿**：用户设备实际提供什么由WebXR运行时决定；桌面键鼠是模拟输入，不能当作真实追踪。
- **空间主场选择**：谁提供场景由会话决定，与房间创建者身份独立。
- **坐标标定**：使同一物体在A/B不同局部帧下映射一致；只有数学变换并不保证真实空间已扫描或安全可走。
- **传输层**：WebRTC/WebSocket负责运送媒体/位姿，不会自动修正不同设备的坐标误差。
- **用户授权**：空间ready不代表可以触碰；每次触碰还需接收方确认与本地安全检查。

## 小例题与验收
设A、B的原点到共享世界只有平移+1m、+3m，A测得手点x=0.2m。先算其B坐标，再考虑两端有旋转时矩阵如何组合。答案见[Day13参考答案](../TASK_GUIDES/ANSWERS/day-13.md)。

**完成标准**：解释WebXR与OpenXR区别，画坐标变换和版本流；不看资料说出“媒体连接成功、双方空间确认、每次触碰许可”三道独立门。现实头显精度/漂移与空间锚点持久性没有实际数据时必须标明未验证。

# R21｜OpenXR：多设备空间参考系不是网络自动同步（Day13）

**权威**：[Khronos OpenXR 1.1 Reference Spaces](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#spaces)。这是规范阅读，目标是理解姿态、时间和失效条件，而非记住所有 C API。

## 只读这四块（约40–45min）
1. Reference space 的概念：VIEW / LOCAL / STAGE（可用与实际行为依设备和运行时）；为什么位置要相对于**某个参考系**？
2. `xrLocateSpace`：哪个空间相对于哪个 baseSpace？指定 time 为何重要？
3. Pose valid/tracked 标志：姿态测量暂时失效时不能把旧结果当实时有效。
4. 多设备共享锚点属于应用/平台协同能力，不可简单以本地 LOCAL 原点相同为前提。

## 手画坐标链，关联Rove
`HMD_A_LOCAL → SHARED_ANCHOR ← HMD_B_LOCAL`。用矩阵表示将 A 的手掌位姿转到 B 的世界：
- 先明确每个 `T_target_source` 的命名方向；
- 再组合变换；注意两台设备的时钟、跟踪置信度不自动一致；
- 若 A 端突然失去跟踪，应冻结、淡出或停止触觉动作，不能继续盲目推送预测接触。

## 闭卷回答
- VIEW 与 LOCAL 意义有何差异？
- 为什么WebRTC链接正常但两个VR用户会出现在不同位置？
- 丢失tracking和丢失网络分别触发什么恢复策略？
- 机器人远程操作中为什么空间映射错误会产生安全风险？
